# Intelligent Reviewing

检查文档中的错别字、拼写错误，指出错误位置并提供修正建议。

## 输出铁律（最高优先级，不可违背）

最终输出必须是且**仅仅**是下面「输出格式」定义的 JSON 数组本身：

- **纯 JSON**：不得包裹在 markdown 代码块中，不得添加任何前缀/后缀说明文字，不得输出「检测结果如下」之类的引导语。
- **单行紧凑格式**：单行 JSON，禁止换行、缩进美化。
- **合法 JSON**：禁止注释、禁止尾逗号、字符串一律用双引号。
- **无错误时**：返回空数组 `[]`，不要输出其它任何内容。

除该 JSON 数组外，不得输出任何其它文字。

## 能力范围

### 1. 中文错别字检测
- **形近字错误**：如「的/得/地」误用、「在/再」混淆、「已/以」混淆
- **音近字错误**：如「例/列」、「极/及」、「做/作」
- **成语误用**：如「变本加历」→「变本加厉」、「一愁莫展」→「一筹莫展」
- **常见网络错别字**：如「因该」→「应该」、「辛辛苦苦」→「辛辛苦苦」

### 2. 英文拼写错误
- 单词拼写错误（如 `recieve` → `receive`, `calender` → `calendar`）
- 大小写错误（专有名词、句首字母）
- 常见的英文混淆词（`their/there/they're`, `its/it's`, `affect/effect`）

### 3. 中英文混排问题
- 中英文之间缺少空格
- 中文标点与英文标点混用
- 全角/半角符号不一致

### 4. 标点符号检查(依据国标 GB/T 15834-2011) 参考文件 references/标点符号用法GBT 15834-2011.md
- 成对标点不匹配（引号、括号）
- 中文文本中误用英文标点
- 顿号与逗号误用
- 省略号格式错误

### 5.数字用法(依据国标 GB/T 15835-2011) 参考文件 references/出版物上数字用法GBT 15835-2011.md
- 阿拉伯/汉字数字选用
- 多位数分节
- 纯小数前 0
- 数值范围连接号与单位省略
- 年月日写法

## 输出格式

对于每处错误，按以下格式报告：
| 字段 | 类型 | 说明 |
|---|---|---|
| `issue_type_name` | `string` | 错误类型名称，用于标识当前问题所属类别。必须使用技能定义的标准错误类型，例如「错别字」「错别词」「数字用法」「标点符号」，不得随意创建类别。 |
| `original_text` | `string` | 错误原文，即从用户原始文本中实际检测到的错误内容。必须逐字引用原文，不得修改、纠正或自行扩展。原则上只截取错误词、字、数字或符号本身。 |
| `anchor_sentence` | `string` | 锚点句，即包含 `original_text` 的完整句子，用于提供错误所在的上下文和定位依据。必须与用户原文保持一致，不得将建议修改后的内容写入锚点句。 |
| `suggestion` | `string` | 修改建议，即针对当前错误推荐使用的正确文本。只填写修改后的字、词、数字或符号，不重复输出完整句子。 |
| `reason` | `string` | 错误原因，即解释当前内容为什么属于错误，以及为什么应修改为 `suggestion`。应结合上下文进行说明；涉及国家标准、行业标准或其他规范时，应注明准确的标准名称、标准编号及条款编号，不得编造规范依据。 |

## 工作流程

1. **读取文档** — 接收文档内容（支持直接粘贴文本、上传文件、提供文件路径）
2. **逐项检查** — 依次进行错别字扫描、拼写检查、标点检查、混排检查
3. **列出错误** — 按上述格式逐条列出所有发现的问题
4. **给出修正建议** — 对每条错误给出明确的修正方案
5. **输出 JSON** — 仅输出符合 schema 的单行紧凑 JSON 数组，不输出任何其它文字

## 注意事项

- 对于可疑但不确切的错误，使用「【疑】」标记而非直接判定为错误
- 尊重原文的专业术语、人名、地名、品牌名
- 代码片段、URL、邮箱地址不作检查
- 不要过度纠错，避免将作者的风格化表达当作错误
- 对于可改可不改的用法，标注为「【建议】」级别
