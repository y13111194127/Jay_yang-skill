# 篇幅、时长与格式规则

## 篇幅优先级
用户明确字数/时长 > 用户明确格式 > 文种常规长度。篇幅控制不能突破真实性，不得通过重复、空话或虚构凑字数。

## 字数目标
若用户给出“约 N 字”，内部目标区间一般控制在 N 的 ±10%；若用户要求“控制在 N 字以内”，不得超过 N；若用户给出明确上下限，严格落在范围内。

标题、称谓、落款是否计入字数由用户说明；未说明时，按正文主要内容控制，不为少量标题称谓差异牺牲结构。

## 时长换算
仅在用户以分钟指定时长、且没有另给字数时使用内部估算：
- 正式中文现场讲话默认按约 220—260 字/分钟规划；
- 需要停顿、互动、强调较多的演讲或致辞按区间偏低值；
- 信息密集、宣读式稿件可按区间偏高值。

这是写作规划估算，不在最终正文中解释。若用户明确指定自己的语速，服从用户值。

## 扩写
扩写优先增加：
1. 已有事实的必要背景；
2. 事实之间的逻辑；
3. 已有问题的影响或表现；
4. 已给任务的执行层次；
5. 责任、协同、节点和反馈；
6. 不改变事实的意义说明。

禁止通过新造数据、政策、案例、成绩或重复观点扩字数。

## 缩写
删除顺序：
1. 同义重复；
2. 万能过渡和套话；
3. 次要背景；
4. 冗余修饰；
5. 非关键例子；
6. 可由上下文恢复的重复结论。

必须保留：核心观点、关键事实、关键数据、政策名称、重要任务、责任、时间节点和原文必要逻辑。

## 标题
- 用户给定标题必须保留，除非任务明确要求修改标题。
- 从零起草而用户未给标题时，可按文种和场景生成事实安全的概括性标题，不得擅自加入具体会议届次、地区荣誉或政策口号。
- 非现场宣传稿、公开信、感谢信通常保留标题；现场讲话可按用户格式决定是否需要标题。

## 小标题
- 只有内容层次需要或用户要求时使用。
- 同级标题应逻辑平行，不强求字数完全一致。
- 不默认使用“一、二、三”式标题；使用时必须确有可枚举的同级任务。

## 序号
推荐层级：
`一、` → `（一）` → `1.` → `（1）`

避免超过 4 层。用户已有编号体系时，校核任务优先保留并纠正明显不一致。

## Markdown
用户未禁止且系统允许时，标题和小标题可用 Markdown；正文内容保持正式文本。若用户明确要求纯文本、公文版式或可直接粘贴到 Word，则不用 Markdown 标题符号。

## 完整公文要素
本技能主要产出讲话与政务应用文本，不自行伪造发文字号、签发人、版记、印发机关等法定公文要素。

“完整公文要素”若用户确实要求，应仅使用用户明确提供的要素；缺失部分使用批准占位符，不得自行编造。

## 落款与日期
- 公开信、感谢信等书面文种按需求保留署名和日期。
- 署名、日期未提供时使用 `〔待补充〕`，不得自动填入当前日期或虚构机关名称。
- 现场讲话稿通常不在正文末自动加落款日期，除非格式要求明确。
