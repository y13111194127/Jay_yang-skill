# 错误示例与边界案例

## 边界 1：附件前缀存在但 JSON 损坏
错误行为：忽略前缀，直接知识库检索或根据文件名写稿。

正确行为：不调用工具，进入素材失败路由，按目标文种使用占位符生成最小结构。

## 边界 2：附件 `files` 为空
错误行为：自动改用知识库。

正确行为：附件元数据异常，进入素材失败路由。

## 边界 3：同一附件 id 重复出现
错误行为：每出现一次调用一次读取工具。

正确行为：按 id 去重，只读取一次。

## 边界 4：附件无关
错误行为：读取后发现无关，再调用知识库补齐。

正确行为：合法非空附件前缀已锁定附件路由；没有有效相关素材时进入失败路由。

## 边界 5：非从零任务带附件
错误行为：读取附件寻找原文。

正确行为：只处理消息正文中的原文；无原文时只输出 `〔待补充原文〕`。

## 边界 6：材料写“计划建设 10 个项目”
错误改写：`已建成 10 个项目。`

原因：把计划状态改成完成状态。

## 边界 7：材料写“取得阶段性进展”
错误扩写：`取得显著成效，群众满意度大幅提升。`

原因：提高成效强度并虚构群众评价。

## 边界 8：政策名不完整
错误行为：凭常识补全政策全称和文号。

正确行为：绕开具体名称或使用 `〔待核实〕`。

## 边界 9：主持词缺议程
错误行为：自行生成五项常见会议议程。

正确行为：保留主持词最小结构，议程处使用 `〔待补充〕`。

## 边界 10：主要领导讲话
错误行为：全文写成操作手册，逐字段说明基层怎么填表。

正确行为：突出方向、任务、统筹和责任，只有材料明确要求时才保留关键操作细节。

## 边界 11：平行单位交流
错误行为：`你单位必须于本周五前完成整改。`

正确行为：使用协商、衔接和共同推进语言，除非发言人确有相应管理权限且素材明确。

## 边界 12：降 AI 味
错误行为：加入“说白了”“咱们”“狠狠抓”“太给力了”等口语或网络词。

正确行为：通过删套话、调整句式、减少机械排比和提高事实密度实现自然表达。

## 边界 13：篇幅不足
错误行为：重复同一观点三次或增加虚构案例凑 3000 字。

正确行为：优先展开已有事实的背景、逻辑、措施、责任和节点；仍无素材时允许低于目标长度，不突破真实性。

## 边界 14：当前日期
错误行为：公开信未提供日期，自动使用系统当前日期。

正确行为：输出 `〔日期待补充〕`，除非用户明确要求使用当前日期且系统提供了可靠当前时间。

## 边界 15：输出纪律
错误输出：`好的，以下是优化后的讲话稿：……如果需要我还可以继续修改。`

正确输出：只包含目标正文，第一个字符和最后一个字符均属于目标文本。
